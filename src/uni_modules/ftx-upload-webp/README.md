# APP 上传 WebP

供识别照片、用户头像、群聊头像的共用压缩入口使用。Android 使用 Bitmap 原生编码；iOS 使用 ImageIO 缩略解码和 SDWebImageWebPCoder。照片最长边 800px，头像最长边 256px；头像保留透明度，编码前校正照片方向，不放大小图。

编码在原生串行后台队列执行，先缩略解码，避免将原始大照片完整解码到内存。JS 最多等待 4 秒；原生任务也检查截止时间，超时生成的文件会清理。缺少编码能力、失败、超时或小图转码后变大时，调用方沿用 plus.zip 的 JPG / PNG 压缩；上传完成后清理压缩临时文件，不删除用户原图。服务端仍负责最终 WebP 存储。

## 打包

这是 UTS 混编原生模块，不能只发布 WGT 更新激活新增能力。请使用支持 UTS 混编的 HBuilderX 重新制作自定义基座／正式 APP 包。Android 打包会解析 `androidx.exifinterface:exifinterface:1.4.2`；iOS 打包会解析 CocoaPods 的 `SDWebImageWebPCoder 0.15.0` 及其依赖。原生依赖解析失败必须修复后重新打包，运行时回退不能替代构建依赖。

## 真机验收

Android / iOS 分别检查相机竖拍、相册横拍、大照片和透明 PNG 头像：上传副本为有效 WebP、方向与透明度正确、尺寸符合上限，后端能接收及展示。模拟编码异常／超时应仍可上传 JPG / PNG，原图不被删除。H5、小程序不导入此原生模块，继续各自现有压缩路径。
