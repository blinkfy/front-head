# APP 圆码扫码接入

> 2026-10-30 当前状态：服务器已移除 Java/unidbg，改由生成端/受控工作端登记原始载荷。Android 0.1.17 新增无相机图片解码；网页保留圆码提示。具体启用方式、权限和未覆盖的平台见 [生成登记说明](roundcode-client-registration.md)。下文旧版本中的服务端解码与 H5 圆码联网为历史记录。

## 范围与发布前提

Android APP 使用 `src/uni_modules/ftx-qbar` 的 UTS + Java/Kotlin 原生插件。
首页浅色/深色和设备连接页复用 `scanDeviceQrCode()`。普通二维码仍走原有业务处理；微信小程序保留原 `path/scene` 处理。

当前 QBar 二进制支持 Android 6+、ARM64、4 KB 内存页。iOS、较旧 Android、32 位进程、其他 CPU、16 KB 内存页设备、缺少插件的旧基座都回退普通二维码；没有把 Android `.so` 当作 iOS 实现，也不为圆码能力提高整个 APP 的最低 Android 版本。

本轮按要求不生成 APK、不提交云打包。Android Java 已用官方 Android 35 `android.jar` 编译检查；UTS/Kotlin 的 HBuilderX 联编、权限和摄像头表现仍须在自定义基座/真机验证，不能将桌面测试称为真机识别率保证。

## 先准备依赖，再由维护者打包 APP

在 `front-head` 中，使用已有 Python 环境和 JDK 11+：

```powershell
$env:JAVA_HOME = 'D:/Java_SE' # 按实际 JDK 根目录修改
python scripts/prepare-qbar-integration.py
```

此命令校验固定提交的资源 SHA-256，生成：

- `src/uni_modules/ftx-qbar/utssdk/app-android/libs/qbar-native.aar`：包含 `classes.jar`（扫描 Activity、解码器和全部 JNI 类）、ARM64 原生库、Activity 清单与 JNI 防混淆规则。
准备脚本仅生成 Android 依赖，不再下载 Maven 或导出后端 Java 运行资源。Android 编译仍需要 JDK，这与服务器运行时无关。

这些可重建二进制被 Git 忽略；仅拉取源码不会自动得到原生能力。准备好后，用支持 UTS 原生混编的 HBuilderX（4.26+）重新制作自定义基座/正式包。前端热更新不能给旧安装包增加 `.so`。无需为本功能修改已有 ABI 列表或账号接口。

### 0.1.1 缺类闪退修正

原 0.1.0 依赖 AAR 只包含 `.so`，Java 源码单独编译通过并不代表已经进入运行包。标准/旧基座可能只有热更新的 Kotlin 桥接，验证其自定义 `ScannerActivity$ResultCallback` 时便抛出 `NoClassDefFoundError`。

0.1.1 把四份 Java 源统一放在插件的 `native-src/android/`，由准备脚本编译进 AAR 的 `classes.jar`。平台混编目录不再保留另一套 Java 源，避免重复类。桥接使用 Android `ValueCallback` 与受保护的反射，不再在签名/匿名类中直接链接 AAR 类型；缺类、缺方法或清单未注册时返回不可用并转普通扫码。

本地只重建依赖可运行（不生成 APK、不改后端资源）：

```powershell
python scripts/prepare-qbar-integration.py --android-only
python -m unittest discover -s scripts -p test_qbar_android_aar.py -v
```

可用 `--android-jar` 或 `ANDROID_JAR` 指定已有 Android SDK；没有 SDK 时仅缓存校验过的官方编译用 `android.jar`，不安装整套 SDK。准备脚本会校验 AAR 内的全部关键类、原生库和清单，拒绝旧的 native-only AAR。

修复后先停止旧运行进程，再重新生成并安装包含更新 AAR 的自定义基座后运行。只同步页面/Kotlin 热更新时，安全回退普通扫码是预期行为，圆码能力仍需完整新基座。

本次回归：AAR 内 11 个 Java 类完整，4 项 AAR 检查与前端扫码脚本通过；Kotlin 桥接编译通过。在隔离 JVM 中刻意不提供 `ScannerActivity`，确认能力检查返回 false、启动回调 UNAVAILABLE、取消不崩溃。这是缺类边界验证，不替代安装新基座后的真机扫码验证。

Java 包装器来自固定提交 `sollyu/wechat-scanner@8ba599fd90216d1ba148eda4cd051eb86cc5b16d`，保留了上游许可文件。其 `.so` 是从微信提取的闭源库；包装器 LGPL 许可不代表腾讯二进制已有商用再分发授权。正式发布前须确认该依赖的发布权利。

## 后端部署

服务器只需现有 Node 服务，不需要 Java、unidbg、JNI 或旧的 native/qbar 资源包；Dockerfile 也不再安装 JRE。本地残留的解码运行资源由 .dockerignore 排除，离线实验不属于生产依赖。

微信接口仍正常生成小程序码，微信/小程序按原 path/scene 识别。生成图片不再启动服务端解码；新的原始载荷索引可由生成时签发的短期任务凭证登记。旧的图片识别/预热接口返回 HTTP 501 和 ROUND_CODE_UNSUPPORTED；旧客户端可安全回退。

## 精确匹配与设备连接

Android 本地 QBar 仍可读取 WX_CODE 并发送原始内容 Base64。resolve-raw 使用已有或客户端新登记、尚未过期且 AppID 一致的精确索引，继续执行设备 token/会话的原有业务校验；Redis 异常不降级猜测参数。

新圆码缺少索引时返回 HTTP 501 / ROUND_CODE_UNSUPPORTED，APP 提示改扫普通二维码或用微信扫码。不采用载荷截断、图片相似度或客户端自报映射代替服务端核验。旧索引过期、重启失去内存缓存后亦不能继续依靠它解析。

## APP 扫网页登录码并确认

APP 必须先登录有效账号；无需微信临时 code，网页登录使用当前 APP 账号。

存在有效精确索引（包括生成任务新登记）时，以下 APP 授权路径可用；未登记的新圆码继续回退。

1. 圆码精确匹配返回 `kind=registration` 和短期 `sessionId`，不返回网页登录 JWT。
2. `POST /api/registration/sessions/:id/app-scan`：验证 APP JWT 和用户仍存在，以账号身份原子占用会话，网页显示“请在APP中确认”。
3. APP 显示当前账号与网页相同的六位确认码。用户取消则调用 `app-cancel`；未确认不会授权。
4. `POST /api/registration/sessions/:id/app-authorize`：重新验证用户、同一扫码账号和 `confirm=true`，标记 authorized。
5. 网页仍通过原 status → consume 流程一次性领取正常登录结果。

APP 不接管已由其他 APP 账号或微信身份占用的会话。APP 切换账号、过期、取消、已领取、数据库不可用均拒绝继续；并发 consume 只允许一个成功。不改变原小程序微信扫码授权路径、账号合并或 JWT 格式。

## 识别与回退

- 原生库异步初始化，单个扫码界面/串行解码；不会在首页加载时创建相机。
- 实时预览限帧、只保留一个处理中的灰度帧；三秒内两个不同相机帧读出一致结果才确认（无结果的间隔帧不立即清空，冲突/多码会重置）。
- 优先选择正常视角、支持自动对焦的后摄；相机仅暴露一个后摄时使用该相机，无法通过旧 Camera API 强制厂商隐藏的物理镜头。选定镜头后复用选择，打开失败才回退其他后摄。预览按传感器旋转后的宽高比居中完整显示，不再拉伸填满。连续自动对焦（兼容 video/auto）、点击对焦、手动补光；低对比度时有限次灰度拉伸。
- 相册对整图尝试有界多尺度/对比度增强，处理 EXIF 旋转/镜像；读取最大 16 MB，采样尺寸有上限。普通尝试失败后再执行几何重试。
- 多码不自动选择；未知圆码不进入普通设备 ID 解析器。
- 页面暂停立即释放相机，退出后在串行任务尾部释放 native handle；图片和私有临时文件及时释放。
- 用户取消不自动打开另一轮扫码；插件不可用或用户选择“普通扫码”时才回到原扫描器。
- 旧后端缺少新接口时明确提示使用普通码/微信，不循环请求或自动重试授权。

## 0.1.2 镜头、预览比例与变形重试

- `ScanGeometry` 是无 Android 依赖的灰度双线性重采样器：12 个有限候选覆盖横/纵 1.4、1.8 倍伸展，两对角方向 1.6 倍伸展，正负斜切以及横纵正负轻度投影。按变换后四角扩展白色画布，保留整图，不裁码、不推测业务参数。
- 原生引擎始终先识别原图。实时预览最大 1920×1080（以设备实际支持为准），默认 1 倍，支持双指在硬件允许范围内放大至 3 倍；仍为 280 ms 节流、单线程单帧处理；失败后每 700 ms 批量最多两个几何候选，单批开始新候选的时间预算 220 ms，长边不超过 960。成功候选优先用于下一帧确认。
- 相册原有三次多尺度尝试均失败后，最多十二次几何重试，启动新候选的总预算 1500 ms。预算在候选之间检查，无法中断一次正在执行的 native 调用。
- 两次相机结果必须在三秒内一致；超时、不同结果、多个码都会重置或重新计数。几何尝试不会绕过后端完整字节匹配和业务凭据有效性校验。
- `scripts/test_qbar_geometry.py` 编译真实纯 Java helper 检查镜头评分、等比预览和重采样边界；`--native` 选项使用本地样本与真实 native 引擎进行变形回归，输出内容哈希、不输出载荷。
- 重新准备依赖 AAR 后，需重新生成并安装自定义基座才能使用这些 Java 修改；仅热更新不生效。没有生成 APP/APK。

相机视角/对焦元数据依赖设备厂商，镜头选择是兼容性优先的启发式。极端压缩、遮挡、模糊造成的信息丢失无法靠重采样恢复，仍需真机验证实际镜头和识别速度。

### 区分圆码识别与后端解析

若 APP 显示“服务器未提供解析接口（HTTP 404/405/501）”，说明 native 已返回 `WX_CODE`，失败在后续 `POST /api/device/wechat-qr/resolve-raw` 请求。先核对 APP 的 `src/api/config.js` 域名，更新该域名实际提供服务的后端并重启进程，检查代理保留 `/api` 路径和 POST 方法；这类错误不是镜头/透视识别失败。

此仓库已有该 route 和 controller。后端还需按前文部署 Java 和 `native/qbar` 运行资源以在生成码时登记索引；多副本需共享 Redis。部署完成后刷新设备码或网页登录码，未登记的旧码不会猜测 scene。缺少索引通常为 422，缓存异常为 503，应与路由不存在区分。不要在日志中输出扫码载荷或 JWT。

### 本轮离线验证记录

Android Java 编译/依赖 AAR 完整性四项测试、APP 旧后端 HTTP 404/405/501 回退测试、几何纯 Java 数学测试及本轮文件空白检查通过。真实圆码样本经 60% 横向压缩后可由候选校正恢复；斜切、轻度透视、10% 对角透视、40% 缩小居中、1.4 倍完整放大均读出与原图相同的内容。测试仅比较类型/长度/内容摘要，不输出载荷。

## 0.1.3 自动放大（已被下述 0.1.4 规则取代）

- 实时相机初始 1 倍。持续没有解码结果约 1.8 秒后，以至少 1.3 秒间隔尝试 1.2、1.45、1.75、2.1、2.5、3 倍；受镜头实际倍率上限约束。达到上限后回 1 倍停留约 3.5 秒，再开始下一轮，防止大码被放大裁切后一直无法识别。
- 这是无结果时的有界变焦尝试，不声称已检测到远处二维码。第一次读出内容及多码时暂停变焦；两帧内容确认、后端解析与授权校验继续沿用原规则。相册不自动变焦。
- 双指操作立即进入手动模式，本次扫码不会自动抢回控制权。倍率提示显示硬件读取回来的实际倍率；点击倍率提示可回到 1 倍并恢复自动。
- 镜头不支持变焦或驱动拒绝变焦时停止自动尝试，保留正常扫码和回退。没有单独的定时器，自动变焦只在当前相机帧处理完成后执行，页面隐藏/退出时停止。
- 当前基座的新页面提示为“请完整入框，支持自动放大与双指缩放”，日志标记 `scanner=0.1.3`。Java/AAR 改动需重新制作并安装自定义基座；未打包 APK。
- 纯 Java 回归覆盖启动延迟、步骤节流、硬件倍率上限、回 1 倍、识别暂停、手动锁定与恢复自动。仍需真机确认厂商驱动的实际变焦效果。

## 0.1.4 小码候选驱动变焦

以本节为准，删除上一版“识别不到就按时间循环放大”的触发方式。

- 对未解码的实时灰度帧执行有界粗检（长边最多 640），通过水平/垂直交叉校验和三个同类定位图案的几何关系，寻找普通 QR 方形定位点或微信圆码环形定位点。使用三个定位点估计整码位置和大小；超过一个不一致候选时放弃自动选择。
- 必须连续至少三帧候选稳定（相邻不超过 1200 ms，中心偏移不超过 0.06，大小变化不超过 40%），码估计边长小于画面短边的 28%，且位于中央区域，才允许增加倍率。每次最多当前倍率的 1.25 倍，间隔至少 1300 ms，上限仍受硬件和 3 倍约束。
- 无候选、候选丢失/不稳定、码已足够大、偏离中心、多码或已解码时均不增加倍率。移除无候选定时放大、到上限回 1 倍循环逻辑。用户可双指调整或点击倍率提示回到 1 倍并恢复自动模式。
- 该粗检只决定相机变焦，不生成扫码结果/scene，不参与授权；实际扫码仍由 QBar 解码并经原后端规则校验。极小、遮挡、弱光或强透视下无法可靠看出定位点时不会自动变焦，需手动靠近或缩放。
- 隔离 native 实验中，当前无检测模型且 `detector=false` 的 QBar `GetCodeDetectInfo/GetZoomInfo` 返回 -2，无法提供小码边界；因此没有把未验证的 native 接口接入 APP。
- 新版页面提示“小码居中可自动放大，支持双指缩放”，日志 `scanner=0.1.4`，需重新制作并安装自定义基座。没有打包 APK 或部署服务器。

## 0.1.5 原生扫码页面与会话稳定性

- 原生页面使用深绿背景、独立返回入口、相机等比取景区与绿色四角引导。`ScanPreview` 在测量/布局阶段同步约束 SurfaceView 和引导层比例，允许留边，不拉伸到手机长宽比。引导层不裁剪参与解码的相机数据。
- 低频扫描线仅在前台相机预览有效时绘制，退出/隐藏停止；点按会在实际触点显示对焦框，并将触点逆旋转映射到 Camera1 对焦/测光坐标，随后恢复连续对焦，带旧请求序号校验与超时兜底。
- 增加 44dp 以上的“−/实际倍率/＋”操作区，保留双指缩放和候选驱动自动变焦；点击倍率回 1 倍并恢复自动。补光显示真实开关状态，不支持时禁用。相册、系统扫码和权限/相机失败后的点按恢复入口均可达。
- 相机优先尝试最高 1920×1080 的受支持预览，驱动拒绝时重试 1280×960；帧大小有界。Camera 错误回调会释放当前会话并提供重试提示，单个异常帧不立即关闭扫码页。
- 每个相机会话有递增序号。帧到达和异步结果提交均核验相机实例与会话，暂停/相册/退出后旧帧不能触发结果或变焦；仍限制单个待处理帧并复用三块相机缓冲。
- 相册解码完成时若页面不在前台，暂存结果，回前台后才处理。关闭页面则丢弃结果，串行任务末尾释放引擎；重复取消和结果仍只回调一次。
- 扫描期间保持屏幕常亮，退后台释放；普通码原始字符集名称无效时按 UTF-8 读取，避免一次字符集异常中断页面。

## 0.1.7 候选检测、同步取景与网页自动圆码

- 通用请求层开始转发有效 timeout 参数，圆码图片接口原有 12 秒设置及预热接口 8 秒设置实际生效；未指定或无效参数保留平台原默认值。扫码器另对圆码模块加载设置 6 秒、只读识图阶段设置 14 秒保护，不对用户确认弹窗计时；超时/关闭后的迟结果不得授权或再次派发成功。
- 验证包含原生 API/mock 异常回退、实际 jsQR 解码 canvas 视频、慢圆码与普通码竞争、授权阶段互斥、关闭后清理、单请求与迟结果、超时转发，以及扫码模块的 Vite 内存生产构建。真实浏览器使用模拟视频流和受控网络，不代表不同手机原生 BarcodeDetector 的识别率或真实圆码服务端耗时。
