# 首页识别框

亮、暗首页共用 `src/utils/use-recognition-bboxes.js`，H5、App Vue 页面和小程序采用同一套坐标映射。

- `<image @load>` 提供图片原始宽高；`uni.createSelectorQuery().in(page)` 测量图片组件和外层容器。
- `aspectFit` 的居中留白计入映射，所有定位使用测量得到的 CSS px，不额外乘设备像素比。
- 图片改变后立即清除旧框；图片节点的数字 key、事件 dataset 和测量序号共同防止过期事件覆盖新图。
- 图片加载、标签更新、窗口改变、返回首页时重新测量；图片加载失败或节点不可测时清空框。
- 类别配色固定：可回收蓝色、厨余绿色、有害红色、其他灰色；未识别的类别保留原来的稳定配色。
- 标签检测已放置标签的遮挡，在同一目标的两侧及上下两行以内选择位置，并限制在图片组件区域内。极密集场景选择遮挡最少的位置，不移动目标框。

## 前后端兼容

首页通过 `recognizeImage(file, { bboxRenderer: 'client' })` 声明具备前端绘框能力。上传接口新增可选表单字段 `bboxRenderer=client`：

| 客户端 / 服务端 | 行为 |
| --- | --- |
| 新首页 + 新后端 | `result_img_base64` 返回未绘框图片，`bbox_rendered=false`，首页叠加框 |
| 旧客户端 + 新后端 | 未声明能力，YOLO 仍返回带框图片，`bbox_rendered=true` |
| 新首页 + 旧后端 | 根据旧响应 `aiSettings.detectorMode=yolo` 保留服务端框，避免重复绘制；AI 图片使用前端框 |

新增字段不会改变历史和聊天种子：YOLO 的历史图片及聊天种子继续使用原有带框图片。后端绘图继续保留；ONNX 图像处理已改用 Pillow + NumPy，旧 OpenCV 实现作为显式回退保留。首页支持前端绘框并不意味着可以直接取消历史和旧客户端所需的后端绘图。

## 真机检查

在 App 和微信小程序分别检查亮、暗主题：横图、竖图、方图，多目标；特别检查图片上下或左右留白时框的位置。再检查快速连续换图、识别中切页后返回、结果页改变窗口尺寸。带 EXIF 方向的手机相片需单独检查，不同端图片解码的方向处理不能仅通过浏览器测试确认。
