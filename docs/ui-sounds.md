# 交互音效

默认开启，设置 → 显示与声音中可关闭。此开关只管理交互音效，与消息通知、用户主动播放的语音分别管理。

## 原创素材

六个短音效由 `scripts/generate-ui-sounds.py` 程序合成，未使用第三方音频采样。制作源脚本可通过 Python、NumPy 和 FFmpeg 重新导出 WAV 母版及 MP3。运行示例：

```sh
python scripts/generate-ui-sounds.py --output-dir <输出目录>
```

APP 使用 `src/static/app/sounds/*.mp3`；网页和小程序使用后端 `public/audio/ui-sounds/*.mp3`，通过统一 public 静态服务的 `/audio/ui-sounds/` 路径加载。部署时需同步这六个后端文件，资源失败会安静忽略，不影响业务。两端 MP3 字节应保持一致；合辑和 WAV 母版不进入应用包。

## 触发范围

- 首页：用户选图开始识别、当前请求成功或失败、新生成的效果图实际加载完成。恢复任务、历史结果及引导自动演示保持安静。
- 设备：普通扫码、小程序码解析及重试发起的实际连接成功；状态恢复和自动检查不播放。
- 挑战：连击模式实际判分、服务端完成结算。其他模式不会根据猜测提前播对错音。
- 抽奖：请求成功后转盘开始、转盘停止显示结果。没有循环转动声。
- 商城及预约：服务器确认兑换或预约成功。
- 成就：首次展示新解锁弹窗，一批成就只播放一次。

统一入口 `playUiSound(event, { page, key })` 是非阻塞、失败静默的操作。`page` 约束异步结果所属页面，`key` 标识同一业务结果；页面切换、进入后台、关闭开关后，旧的待播放请求立即失效。普通提示加载超过 650ms 不补播；用户主动试听允许等待 5 秒，失败时显示简短提示。新用户交互可重试加载失败的资源。

网页在用户首次手势中解锁一个 Web Audio 上下文，并复用六个解码缓冲；播放等待浏览器解锁完成，音频地址返回 HTML 时按资源不可用处理。小程序及 APP 使用有限数量的 InnerAudioContext，APP 音效播放音量使用原配置的 1.5 倍（上限 1），网页和小程序保持原音量；APP 采用 ambient 模式，小程序在平台支持范围内遵循系统静音开关。录音和语音聊天页面不插入交互音，网页媒体播放期间暂停交互音。

## 验证

`node scripts/test-ui-sounds.mjs` 验证默认偏好、页面归属、后台与媒体互斥、节流去重、优先级、异步过期及失败降级。实际扬声器听感和原生平台静音行为仍需对应设备验收。

APP 播放直接调用 `play()`，不以 `onCanplay` 作为启动前提，也不在开播前执行 `seek(0)`；小程序保留就绪后播放。APP 的 `obeyMuteSwitch` 在当前 UniApp 实现中为只读，仅通过 `sessionCategory = ambient` 管理静音行为。回归测试包含只读属性及没有预先发出 `onCanplay` 的 APP 播放器模拟。
